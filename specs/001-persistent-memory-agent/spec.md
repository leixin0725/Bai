# Feature Specification: 持久记忆聊天 Agent

**Feature Branch**: `001-persistent-memory-agent`

**Created**: 2026-07-19

**Status**: Draft

**Input**: User description: "写一个聊天 agent：保存并组织长期记忆与短期对话记录，每轮作为提示词注入；通过专门配置文件定义人格；不按对话组织聊天，每次启动继承全部记忆；为多状态人格、工具调用和长期自主循环预留扩展空间。"

## Scope

### In Scope

- 一个跨程序启动持续存在的单一 Agent 身份与连续记忆空间。
- 长期记忆、短期交互记录的持久保存、组织、恢复和每轮提示词注入。
- 由专用记忆整理人格分析交互要点并自动向长期记忆追加内容。
- 统一位置下相互独立的人格配置文件，以及基础、状态和记忆整理人格提示词的加载与校验。
- 采用便于人工直接查看和维护的长期记忆文件，并安全应用有效的人工修改。
- 默认状态及多状态人格提示词的扩展边界。
- 记忆来源查询以外的工具调用和长期自主循环的禁用默认值与可验证扩展边界。
- 所有人格均可按相同方式调用的只读记忆来源查询工具。
- 记忆、人格与扩展行为所需的凭据保护和可诊断性。

### Out of Scope

- 会话列表、聊天线程、创建新对话、选择历史对话或按启动批次隔离记忆。
- 完整的状态迁移决策、记忆来源查询工具之外的生产级工具集合，或无人值守的长期自主执行。
- 多用户权限、跨设备同步、共享记忆和协同编辑。
- 面向最终用户的记忆删除、导出或图形化管理界面；首版仅支持直接维护长期记忆文件。
- 指定交互界面、模型供应方、编程语言、存储产品或部署形态。

## Clarifications

### Session 2026-07-19

- Q: 哪些内容可以写入长期记忆？ → A: 由专用记忆整理人格从交互记录中分析要点并自动追加；其提示词与其他人格提示词在统一位置分别使用独立文件管理，长期记忆文件必须便于人工直接维护。
- Q: 记忆整理人格应在什么时候分析并追加长期记忆？ → A: 仅在一批聊天记录即将移出短期直接注入窗口时批量整理；必须先成功追加长期记忆再修剪该批记录，不需要每轮对话都整理。
- Q: 长期记忆和原始聊天记录在磁盘上应采用哪种隐私保护方式？ → A: 明文保存，仅依赖当前用户的文件访问权限和写入前凭据拒绝或脱敏，不使用应用层加密。
- Q: 移出短期直接注入窗口后的原始聊天记录应保留多久？ → A: 永久明文保留并建立来源索引；每条长期记忆创建时必须指向一条或多条原始来源记录，并支持在特定情况下取回并注入来源原文。
- Q: 哪些情况必须沿来源索引注入原始聊天记录？ → A: 不设置全局自动注入条件；提供统一、只读的记忆来源查询工具，聊天人格和任何辅助人格都能按相同方式调用，调用结果按需进入当前工作上下文。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 跨启动延续同一个 Agent (Priority: P1)

用户与 Agent 进行交互、关闭程序并在稍后重新打开。用户无需选择或恢复某个对话，Agent 即可继续使用此前的长期记忆和短期交互记录回答问题，并保持同一个连续身份。

**Why this priority**: 跨启动记忆连续性是该产品区别于普通聊天程序的核心价值，也是其他人格和扩展能力的基础。

**Independent Test**: 记录一组包含可核对事实和偏好的交互，关闭并重启程序多次，然后直接询问这些内容；无需选择历史对话即可核对所有已确认记录仍可访问且已参与回答上下文。

**Acceptance Scenarios**:

1. **Given** Agent 首次启动且没有任何记忆，**When** 用户完成一轮交互，**Then** 用户输入和 Agent 输出均被保存为连续记忆的起点。
2. **Given** Agent 已确认保存长期记忆和短期交互记录，**When** 程序关闭后重新启动，**Then** 全部已确认记录被恢复，且不要求用户选择会话或聊天线程。
3. **Given** 用户在不同启动周期提供了相互关联的信息，**When** 用户在新启动周期提出后续问题，**Then** Agent 使用跨周期信息形成一个连续回答，而不是把当前启动视为新对话。
4. **Given** 某轮交互在保存完成前发生异常终止，**When** 程序再次启动，**Then** 系统恢复到最近一个完整状态，既不展示半条记录，也不破坏更早记忆。

---

### User Story 2 - 组织长短期记忆并构造每轮上下文 (Priority: P2)

用户持续与 Agent 交互后，近期记录保留在短期直接注入窗口中。当一批记录即将移出该窗口时，专用记忆整理人格批量分析其要点并向长期记忆追加内容。Agent 组织重复或冲突内容，并在每次响应前形成包含人格与记忆的可追溯提示上下文。

**Why this priority**: 仅保存原始记录会随时间增长而失去可用性；组织、压缩和可追溯注入决定长期记忆是否真的能参与聊天。

**Independent Test**: 输入包含重复事实、修正事实、近期任务和超过短期直接注入窗口的历史记录，验证窗口未满时不运行整理，记录即将移出时才批量提取并追加要点，追加失败时不修剪，人工编辑长期记忆文件后修改可安全生效。

**Acceptance Scenarios**:

1. **Given** 存在近期交互和已整理的长期信息，**When** 用户发送新输入，**Then** 当前输入、基础人格、当前状态人格以及组织后的长短期记忆均参与本轮提示上下文。
2. **Given** 多条记录表达同一事实，**When** 系统组织记忆，**Then** 系统可合并其表达但保留原始记录及来源关联。
3. **Given** 用户明确修正了先前信息，**When** 后续提示上下文被构造，**Then** 新信息获得明确优先级，旧信息仍可追溯且不会作为当前事实误导 Agent。
4. **Given** 全部原始记忆超过单次模型输入容量，**When** 构造提示上下文，**Then** 系统使用可追溯摘要和近期原文表达全部记忆范围，同时完整保留未逐字注入的原始记录。
5. **Given** 一批聊天记录仍能完整保留在短期直接注入窗口，**When** 新交互未使其接近窗口边界，**Then** 系统不调用记忆整理人格处理该批记录。
6. **Given** 维护者直接修改了长期记忆文件，**When** 系统加载并校验该文件，**Then** 有效修改在之后的提示上下文中生效，无效修改被拒绝且不破坏最近的有效记忆。
7. **Given** 一批聊天记录即将移出短期直接注入窗口，**When** 长期记忆追加成功，**Then** 系统才从直接注入窗口修剪该批记录，并保留其原始持久记录与长期记忆来源关联。
8. **Given** 一批聊天记录即将移出短期直接注入窗口，**When** 记忆整理或长期记忆追加失败，**Then** 该批记录继续保留为待整理内容且不会被修剪，之后可以重试。
9. **Given** 记忆整理人格从多条聊天记录产生一条长期记忆，**When** 该长期记忆被持久保存，**Then** 同一完整操作建立指向全部来源记录的索引，且每个索引目标都可读取。
10. **Given** 任一人格需要核对某条长期记忆的原始语境，**When** 该人格调用统一的记忆来源查询工具，**Then** 对应的一条或多条原始记录按全局顺序返回，并只进入当前调用流程的工作上下文。
11. **Given** 聊天人格、记忆整理人格和状态辅助人格查询同一条长期记忆，**When** 它们使用相同参数调用记忆来源查询工具，**Then** 工具使用相同权限、结果结构和错误语义返回相同来源集合。

### User Story 3 - 通过独立配置定义人格 (Priority: P3)

Agent 维护者能够在统一的人格配置位置分别使用独立文件定义基础人格、状态人格和记忆整理人格提示词。程序按职责加载对应配置，而不需要把人格散落在业务规则或历史记忆中。

**Why this priority**: 独立人格配置使身份行为可审阅、可替换，也为未来按状态组合多份人格提示词建立稳定基础。

**Independent Test**: 分别加载基础、状态和记忆整理人格文件，并测试缺失、角色重复和无效引用；验证每个流程只使用对应人格，且错误配置不会静默退回到未定义人格。

**Acceptance Scenarios**:

1. **Given** 存在有效的基础人格配置文件，**When** Agent 启动并处理输入，**Then** 基础人格提示词出现在每轮提示上下文中。
2. **Given** 维护者替换为另一份有效人格配置，**When** Agent 重新加载配置，**Then** 新人格应用于之后的交互且既有记忆保持不变。
3. **Given** 人格配置缺失、为空或格式无效，**When** Agent 启动，**Then** 程序给出可操作错误并停止生成响应，不静默使用通用人格。
4. **Given** 基础、状态和记忆整理人格文件位于统一配置位置，**When** 系统加载配置，**Then** 每个文件的职责和引用可独立校验，且记忆整理流程不得使用聊天人格替代专用人格。

---

### User Story 4 - 为状态相关人格预留扩展 (Priority: P4)

未来的状态管理功能能够为 Agent 定义多个有名称的状态，并为每个状态关联一份或多份人格提示词。首版使用默认状态，但提示词组合和记忆记录不得假定永远只有一个状态。

**Why this priority**: 尽早固定状态与人格的组合边界，可以避免未来引入状态机时重写记忆和提示上下文核心。

**Independent Test**: 在不改变记忆保存和基础提示流程的前提下，配置默认状态之外的测试状态及多份状态人格提示词，验证系统能够确定地组合对应内容并标记产生该轮交互的状态。

**Acceptance Scenarios**:

1. **Given** 首版没有启用状态迁移，**When** Agent 处理任意输入，**Then** 每轮都使用明确的默认状态标识。
2. **Given** 某测试状态关联多份有效人格提示词，**When** 该状态被测试性激活，**Then** 基础人格和全部状态人格提示词按确定顺序参与上下文组合。
3. **Given** 某状态引用缺失的人格配置，**When** 构造该状态的提示上下文，**Then** 系统拒绝继续并指出缺失引用，不生成部分人格响应。

---

### User Story 5 - 安全接入未来工具和自主循环 (Priority: P5)

未来维护者可以在不改写记忆、人格和普通单轮交互核心的情况下，接入工具调用或受控的长期自主循环。首版提供统一的只读记忆来源查询工具；其他工具和自主循环默认禁用，并保留清晰的启用、停止、结果记录和权限边界。

**Why this priority**: 工具和自主循环会扩大行为与安全风险；先定义隔离边界可以保证未来扩展不会破坏核心连续性或绕过凭据保护。

**Independent Test**: 让不同人格通过同一调用方式使用记忆来源查询工具，再分别接入一个无副作用测试工具和一个受限测试循环；验证查询结果一致，其他扩展禁用时无影响，启用时可追溯、可停止并遵守凭据规则。

**Acceptance Scenarios**:

1. **Given** 外部工具与自主循环均未启用，**When** 用户正常聊天，**Then** 除按需可用的只读记忆来源查询工具外，Agent 不发起其他扩展行为且核心流程不依赖其他扩展存在。
2. **Given** 一个测试工具被显式启用，**When** Agent 请求调用它，**Then** 调用意图、输入摘要、结果和错误可关联到触发它的交互，但不泄露凭据。
3. **Given** 一个测试自主循环被显式启用，**When** 达到停止条件、次数限制或人工停止信号，**Then** 循环及时停止并保存完整检查点，不影响之后的普通交互。
4. **Given** 扩展试图绕过人格、记忆写入或凭据保护规则，**When** 系统校验扩展行为，**Then** 行为被拒绝并留下不含敏感值的诊断记录。

### Edge Cases

- 首次启动不存在记忆文件或记忆集合时，系统从空的连续记忆空间开始，而不是报告恢复失败。
- 最新写入中途终止或部分数据损坏时，系统恢复最近完整检查点并隔离损坏部分。
- 两个程序实例尝试同时写入同一记忆空间时，系统必须阻止冲突写入或进行不会丢失记录的一致性协调。
- 记忆量超过单轮提示容量时，系统压缩注入内容但不删除原始记录，并提供摘要到来源的追溯关系。
- 新旧记忆互相冲突时，系统区分“当前有效信息”和“历史信息”，不得静默覆盖来源。
- 人格配置文件缺失、为空、无法读取或引用循环时，系统给出具体错误且不产生未定义人格响应。
- 状态没有专属人格提示词时，系统仍使用基础人格；状态引用无效人格时必须失败而不是部分加载。
- 记忆来源查询以外的工具或自主循环扩展未安装、禁用、超时或失败时，普通单轮聊天与已保存记忆仍保持可用。
- 用户输入疑似包含可用凭据时，系统不得把原值写入长期记忆、短期记录、日志或诊断输出。
- 明文记忆文件的访问权限无法限制到当前用户或被外部修改时，系统必须告警并避免在未知内容上继续无提示运行。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供一个可持续交互的 Agent，并把所有程序启动周期视为同一连续身份。
- **FR-002**: 系统 MUST 持久保存每条用户输入和每条已展示的 Agent 输出，并为记录分配稳定标识、顺序和时间信息。
- **FR-003**: 系统 MUST 在生成响应前保存本轮用户输入，并在向用户确认响应前完整保存 Agent 输出。
- **FR-004**: 系统 MUST 分别维护短期逐轮交互记录和经过组织的长期记忆，并保留两者之间的来源关联。
- **FR-005**: 系统 MUST 仅在一批聊天记录即将移出短期直接注入窗口时，使用专用记忆整理人格批量分析其要点，并以追加方式组织适合长期保留的信息。
- **FR-006**: 系统 MUST 在每次启动时恢复全部已确认的长期记忆和短期记录；启动边界 MUST NOT 创建新的记忆分区。
- **FR-007**: 系统 MUST NOT 提供或依赖会话、聊天线程、新建对话或历史对话选择来组织核心记忆。
- **FR-008**: 系统 MUST 在每轮生成前构造包含基础人格、当前状态人格、长期记忆、短期记录和当前输入的提示上下文。
- **FR-009**: 系统 MUST 使用确定、可记录的优先级组织重复、修正和冲突记忆，且不得静默丢弃原始来源。
- **FR-010**: 当全部记忆无法逐字容纳时，系统 MUST 使用可追溯的组织或摘要表示完整记忆范围，并优先保留近期及当前相关原文。
- **FR-011**: 系统 MUST 保留从每个注入片段到原始记忆记录或人格配置的追溯信息，但诊断信息不得包含受保护凭据。
- **FR-012**: 系统 MUST 从统一的人格配置位置加载相互独立的基础、状态和记忆整理人格文件；人格内容 MUST NOT 散落在记忆记录或业务规则中作为替代配置。
- **FR-013**: 系统 MUST 校验每个人格文件的角色唯一性、存在性、非空性和引用完整性；无效时 MUST 阻止受影响流程并返回可操作错误。
- **FR-014**: 系统 MUST 为每轮交互记录明确的 Agent 状态；首版默认使用唯一的 `default` 状态。
- **FR-015**: 系统 MUST 允许一个状态关联一份或多份人格提示词，并按稳定顺序将基础人格与状态人格组合。
- **FR-016**: 状态人格扩展 MUST 能够在不改变记忆存储、恢复和普通提示构造职责的情况下增加新状态。
- **FR-017**: 系统 MUST 提供统一的工具调用边界，定义调用输入、结果、错误、权限和记录行为；除内置只读记忆来源查询工具外，其他工具默认禁用并要求显式启用。
- **FR-018**: 系统 MUST 提供默认禁用的长期自主循环扩展边界，定义显式启动、检查点、停止信号、次数或资源限制以及异常恢复行为。
- **FR-019**: 工具与自主循环产生的结果 MUST 能关联到触发记录和当时状态，但 MUST NOT 绕过基础人格、记忆一致性或凭据保护规则。
- **FR-020**: 系统 MUST 以完整或可恢复的方式写入记忆；异常中断后 MUST NOT 暴露半条已确认记录或破坏更早记录。
- **FR-021**: 系统 MUST 防止多个写入者无协调地修改同一记忆空间，并在冲突时保持已确认记录不丢失。
- **FR-022**: 系统 MUST 提供不泄露受保护内容的诊断结果，用于确认本轮加载了哪些人格、状态和记忆来源，以及扩展是否启用。
- **FR-023**: 系统 MUST 将长期记忆保存在结构明确、可读且有格式说明的文件中，使维护者能够直接查看、追加、修正和调整当前有效性。
- **FR-024**: 系统 MUST 在应用人工修改前校验长期记忆文件；有效修改 MUST 标记为人工来源并在后续上下文生效，无效修改 MUST 被拒绝且不得覆盖最近有效版本。
- **FR-025**: 系统 MUST 跟踪短期直接注入窗口的边界；只有对应长期记忆追加完整成功后，记录才可移出该窗口。整理或写入失败时 MUST 保留原记录与待整理状态并允许重试。
- **FR-026**: 从短期直接注入窗口修剪记录 MUST 只改变后续提示词的直接注入范围，不得删除其原始持久记录或来源追溯信息。
- **FR-027**: 系统 MUST 以无需应用层解密即可直接查看和编辑的明文形式持久保存长期记忆与原始聊天记录。
- **FR-028**: 系统 MUST 尽可能把明文记忆文件的读写权限限制为当前系统用户；无法确认或维持该限制时 MUST 给出明确安全告警。
- **FR-029**: 系统 MUST 永久保留所有已确认的原始聊天记录；移出短期直接注入窗口、生成长期记忆或建立摘要均 MUST NOT 触发原始记录删除。
- **FR-030**: 每条自动或人工创建的长期记忆 MUST 在同一完整写入过程中建立来源索引，指向一条或多条现存原始聊天记录；无有效来源的长期记忆不得被标记为创建成功。
- **FR-031**: 来源索引 MUST 支持从长期记忆定位、排序并读取全部原始来源，使任一人格能够通过统一查询工具按需取得相关原文。
- **FR-032**: 系统 MUST 检测并报告缺失、重复或失效的来源索引，不得把无法追溯的长期记忆静默作为可靠当前事实注入。
- **FR-033**: 系统 MUST 提供一个内置、只读的记忆来源查询工具，能够以长期记忆稳定标识查询其全部原始来源记录和必要的追溯元数据。
- **FR-034**: 基础聊天人格、记忆整理人格、状态人格及未来辅助人格 MUST 通过相同调用格式、权限校验、结果结构和错误语义使用记忆来源查询工具。
- **FR-035**: 系统 MUST NOT 因长期记忆被使用而自动注入其全部来源原文；只有人格显式调用查询工具后，返回原文才可进入该调用流程的当前工作上下文。
- **FR-036**: 记忆来源查询工具 MUST NOT 修改原始记录、长期记忆或索引；调用及其返回来源 MUST 可追溯到调用人格和当前工作流程。

### Core Business Rules *(mandatory)*

- **BR-001 — 连续性**: 一旦交互被系统确认为已保存，它在所有后续启动中 MUST 保持可恢复；正常路径覆盖保存与恢复，边界覆盖空记忆和大量记忆，失败路径覆盖中断与损坏恢复。
- **BR-002 — 单一记忆空间**: 程序启动、关闭和重启 MUST NOT 改变记忆归属或创建会话边界；不同启动周期的记录按同一全局顺序组织。
- **BR-003 — 确认前持久化**: 用户输入 MUST 在生成前持久化，Agent 输出 MUST 在展示前持久化；任一步失败时不得把未保存内容表示为已确认。
- **BR-004 — 原始记录不可因整理丢失**: 摘要、去重、长期记忆提取和冲突处理可以改变注入表达，但 MUST 保留原始记录、来源和当前有效性状态。
- **BR-005 — 每轮注入**: 每次模型生成 MUST 使用有效基础人格、当前状态人格和组织后的长短期记忆；缺少强制组成部分时必须失败而不是降级为无人格或无记忆响应。
- **BR-006 — 冲突优先级**: 明确修正的新记忆优先于被修正的旧记忆；旧记忆保留为历史来源但不得继续作为当前事实注入。
- **BR-007 — 容量降级不等于遗忘**: 超过单轮容量时可以压缩提示上下文，但所有原始记忆 MUST 继续存储、可追溯并在后续组织中保持候选资格。
- **BR-008 — 人格与记忆分离**: 人格配置变化只能影响之后的行为提示，不得改写历史记忆；记忆整理也不得修改人格配置。
- **BR-009 — 扩展默认安全**: 未显式启用的状态迁移、记忆来源查询以外的工具或自主循环 MUST 不执行；扩展失败不得破坏普通聊天和既有记忆。
- **BR-010 — 扩展服从核心约束**: 所有未来状态、工具和循环 MUST 复用同一人格、记忆、追溯和凭据保护门禁，不得建立旁路。
- **BR-011 — 专用人格批量追加长期记忆**: 自动长期记忆写入 MUST 仅由记忆整理人格在记录接近短期窗口边界时批量产生并默认追加；它不得每轮无条件运行，也不得静默删除或原地改写既有来源。
- **BR-012 — 人工维护优先**: 经过校验的人工长期记忆修改 MUST 作为明确来源保留并优先于自动整理结果；记忆整理人格不得静默覆盖人工决定。
- **BR-013 — 先整理后修剪**: 即将移出短期直接注入窗口的记录 MUST 先完成长期记忆整理与持久追加；任一步失败时必须保留在待整理范围，修剪不得先于成功确认。
- **BR-014 — 明文存储边界**: 记忆内容按明确选择以明文保存，系统不得声称其已加密；安全性 MUST 依赖当前用户文件权限和凭据写入防护，权限异常必须可见。
- **BR-015 — 原始记录永久归档**: 已确认的原始聊天记录 MUST 永久保留；任何窗口修剪、长期记忆整理、摘要或冲突处理只能改变使用状态，不能删除原文。
- **BR-016 — 长期记忆与来源索引原子一致**: 长期记忆内容及其一个或多个来源引用 MUST 共同成功或共同失败，系统不得留下无来源的长期记忆或指向不存在记录的已确认索引。
- **BR-017 — 人格统一查询**: 所有人格 MUST 使用同一个记忆来源查询契约；不得为聊天人格或任一辅助人格建立具有不同结果或绕过权限的专用旁路。
- **BR-018 — 原文按需且只读**: 来源原文只有在某个人格显式调用查询工具后才进入该流程上下文，查询 MUST 保持只读且不得把结果自动扩散到无关流程。

### Sensitive Credentials *(include if applicable)*

- **CR-001**: 系统 MUST 通过受控的外部配置接收模型服务或未来工具所需凭据，且人格配置和记忆文件 MUST NOT 包含可用凭据。
- **CR-002**: 系统 MUST 在写入长期记忆、短期记录、日志和诊断输出前拒绝或脱敏疑似可用凭据，并明确告知用户未保存原值。
- **CR-003**: 工具与自主循环 MUST 仅获得其被明确授权的凭据能力；凭据值 MUST NOT 进入模型提示上下文或扩展调用记录。
- **CR-004**: 示例、测试和错误信息 MUST 仅使用明确无效的占位符，并支持在疑似泄露后撤销、轮换和检查受影响记录。
- **CR-005**: 由于记忆文件采用明文，系统 MUST 在持久化前拒绝或不可逆脱敏可用凭据，并 MUST 检查和报告过宽的文件访问权限。
- **CR-006**: 记忆来源查询工具 MUST 应用与直接文件读取相同的凭据脱敏和当前用户权限边界，且不得通过工具结果恢复已被脱敏的值。

### Key Entities *(include if feature involves data)*

- **记忆记录（Memory Record）**: 一个稳定、可排序且可追溯的记忆单位，包含类型、内容或安全引用、来源、创建时间、有效性、关联状态及组织关系。
- **短期交互记录（Short-Term Interaction）**: 用户输入或 Agent 输出的逐轮原始记录，保持全局顺序，不归属于聊天会话；其中近期一段构成每轮直接注入窗口，移出窗口不等于删除原始记录。
- **长期记忆项（Long-Term Memory Item）**: 从一个或多个原始记录组织出的持久事实、偏好、约束或事件，保留来源与冲突状态。
- **记忆来源索引（Memory Provenance Index）**: 长期记忆与一条或多条原始聊天记录之间的可校验关联，用于来源审计、冲突处理和按需原文注入。
- **记忆来源查询工具（Memory Source Query Tool）**: 所有人格以统一方式调用的只读能力，根据长期记忆稳定标识返回有序来源记录、追溯元数据或一致的错误结果。
- **人格配置（Persona Profile）**: 统一配置位置中按职责独立保存、可校验且可版本化的基础、状态或记忆整理人格提示词。
- **记忆整理人格（Memory Curator Persona）**: 专门分析短期交互要点、生成可追溯追加项并服从人工维护结果的人格配置角色。
- **Agent 状态（Agent State）**: 产生某轮交互时的稳定状态标识及其人格提示词集合；首版包含 `default`，未来可增加转换规则。
- **提示上下文（Prompt Context）**: 每轮生成使用的人格、状态、长短期记忆和当前输入的有序组合，并保存来源追踪信息。
- **扩展声明（Extension Declaration）**: 状态能力、工具或自主循环的标识、启用状态、权限、限制和结果记录约定。
- **恢复检查点（Recovery Checkpoint）**: 最近一次确认完整写入的连续记忆位置，用于异常后恢复而不暴露半成品。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在包含 100 轮交互和 10 次程序重启的连续性测试中，100% 已确认输入与输出保持可恢复、顺序一致且无需选择历史对话。
- **SC-002**: 对所有验收测试生成的响应，100% 都能确认有效基础人格、当前状态和记忆上下文已参与本轮构造；缺少任一强制项时不生成响应。
- **SC-003**: 当原始记忆体量达到单轮可用输入容量的 10 倍时，100% 原始记录仍可访问，且每个摘要片段都能追溯到其来源记录。
- **SC-004**: 在写入中断、最新记录损坏和重复启动恢复测试中，100% 更早的已确认记录保持完整，且不出现半条已确认记录。
- **SC-005**: 两份有效人格配置产生可辨识的预期行为差异；对缺失、空白和引用无效配置的测试，100% 返回可操作错误且不生成通用人格响应。
- **SC-006**: 至少 3 个测试状态及其多份人格提示词能够通过既定扩展边界被组合，而无需改变记忆保存、恢复和基础人格职责。
- **SC-007**: 一个无副作用测试工具和一个受限测试循环能够分别接入、禁用、启用和停止；所有测试均保持记录可追溯，且不改变未启用时的普通聊天结果。
- **SC-008**: 在目标运行环境中，拥有 10,000 条短期记录和 1,000 条长期记忆时，至少 95% 的启动在 3 秒内使连续记忆可用于首次交互。
- **SC-009**: 凭据泄露检查在人格、记忆、提示追踪、日志、测试和扩展记录中发现的可用凭据数量为 0。
- **SC-010**: 在包含稳定事实、重复信息、明确修正和无关闲聊的窗口边界测试中，窗口边界前不运行整理；边界触发后 100% 自动长期记忆追加项由记忆整理人格批量生成、关联原始记录，且不静默覆盖既有项。
- **SC-011**: 对有效追加、修正、有效性调整和无效格式四类人工维护测试，100% 有效修改在下一次加载后生效，100% 无效修改被拒绝且最近有效记忆保持可用。
- **SC-012**: 在记忆整理失败和长期记忆写入失败测试中，100% 待处理原始记录继续保留且未从直接注入范围提前修剪；重试成功后才完成修剪。
- **SC-013**: 长期记忆和原始聊天记录可由当前用户使用普通文本工具直接读取；凭据测试值持久化数量为 0，且对过宽文件权限的测试 100% 产生安全告警。
- **SC-014**: 在至少 1,000 条长期记忆的来源完整性测试中，100% 长期记忆指向一条或多条存在的原始记录，且任一原始记录移出短期窗口后仍可沿索引读取。
- **SC-015**: 在长期记忆写入或来源索引写入任一失败的测试中，产生的已确认无来源长期记忆数量和失效索引数量均为 0。
- **SC-016**: 基础聊天人格、记忆整理人格和至少两个测试辅助人格使用相同参数查询同一长期记忆时，100% 获得相同的有序来源集合、权限判断和错误语义。
- **SC-017**: 在未调用查询工具的长期记忆使用测试中，自动注入的来源原文数量为 0；调用后返回原文 100% 仅出现在对应流程上下文，且所有查询保持原始记录和索引不变。

## Assumptions

- 首版面向单个用户和单个连续 Agent；同一时刻只允许一个获得写入权的程序实例。
- “继承全部记忆”指全部原始记录跨启动完整保留并参与组织；受模型输入容量限制时允许注入可追溯摘要，而不是要求每轮逐字附带无限历史。
- 首版只有 `default` 状态，状态迁移逻辑不实现；但状态标识、人格组合和记录归属从第一版起必须存在。
- 首版只提供内置的只读记忆来源查询工具，不提供其他真实生产工具，也不启动长期自主循环；其他能力只要求扩展边界、默认禁用、权限约束、检查点和停止语义可被测试替身验证。
- 交互界面、生成模型、存储介质和部署方式在规划阶段选择，不改变本规格定义的连续性和安全行为。
- 长期记忆由专用记忆整理人格在记录即将移出短期直接注入窗口时批量分析并追加；规划阶段确定窗口容量和批量边界，但不得改为每轮无条件整理，也不得把提取规则硬编码为聊天人格的隐含职责。
- 用户可用的记忆查看、删除、导出和多设备同步不属于首版；未来增加这些能力时不得破坏单一连续记忆语义。
- Agent 依赖一个可用的文本生成能力；外部服务不可用时，本轮输入仍应安全保存，并允许稍后重试而不生成伪响应。
- 除被拒绝或脱敏的可用凭据外，维护者接受记忆内容以明文存在于磁盘，并由操作系统用户权限承担本地保密边界。
- 原始聊天记录永久保留；规划必须考虑持续增长的容量监测、备份和索引维护，但不得通过自动删除降低存储占用。
